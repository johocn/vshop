### Task 2: 校正 balance-pay 结果判定（结算失败不得误判成功）

**Files:**
- Modify: `src/pkg-order/pages/checkout.vue`

- [ ] **Step 1: 修正 `payCurrentOrder` 对 balance-pay 的处理**

现状：`addPaymentToOrder` 若结算失败（余额不足/未登录/缺顾客）会返回带 Declined 支付的订单，随后走 `handlePayment('balance-pay')` 直接 `{ success: true }` → 误跳成功页。改为仅在支付真正 Settled/Authorized 时返回 code，否则抛错：

```ts
async function payCurrentOrder(method: string): Promise<string> {
    const paymentMetadata: Record<string, any> = {};
    if (method === 'wechatpay') {
        const openid = uni.getStorageSync('auth_openid');
        if (openid) paymentMetadata.openid = openid;
    }
    const payRes: any = await addPaymentToOrder(method, paymentMetadata);
    const order = payRes.addPaymentToOrder;
    if (order?.state === 'PaymentSettled' || order?.state === 'PaymentAuthorized') {
        // 即时结算类必须真正 Settled 才返回成功
        if (method === 'balance-pay' && order.state !== 'PaymentSettled') {
            throw new Error('余额支付未完成，请重试');
        }
        return order.code;
    }
    // 若存在最后支付且其 state 为 Declined，抛明错误（尤其 balance-pay 余额不足）
    const lastPayment = order?.payments?.[order.payments.length - 1];
    if (method === 'balance-pay') {
        const declined = lastPayment?.state === 'Declined';
        throw new Error(declined ? (lastPayment.errorMessage || '余额不足，支付未完成') : '余额支付未完成，请重试');
    }
    const result = await handlePayment(method as PaymentMethod, {
        ...lastPayment,
        orderCode: order?.code,
        orderState: order?.state,
    });
    return result.success ? order?.code : '';
}
```

### Task 4: 跨店/聚合单余额支付校验（后端）

**Files:**
- Inspect/Modify: `packages/recharge-card-plugin/src/recharge-card.service.ts`

- [ ] **Step 1: 确认跨店/聚合单扣减正确性**

聚合单/拆单场景：每个子订单独立 `balance-pay`，`createPayment` 用 `String(orderWithCustomer.customer.id)` 扣减。核对：
- customer 归属以 `order.customer` 为准（不同商家子单若属同一顾客，余额一致，正确）。
- 每笔扣减的 `channelId = ctx.channelId`，保证跨店同渠道余额账户一致。

- [x] **Step 2: 退款不超单店余额消费额（已有）复核**

`createRefund` 已用 `getOrderBalanceConsumed` 限制退款 ≤ 该订单余额消费额，跨店子单各自独立上限，符合预期。

**复核结论（无需改动后端）：**
- `applyBalanceChange`（delta<0）用原子 `balance - absAmt WHERE balance >= amt` 扣减，不足抛 `Insufficient balance`，防负余额且并发安全。
- 扣减按 `channelId` 隔离账户 → 跨店/同渠道共享同一余额账户，跨店支付正确。
- `isOrderBalancePaid` 按 orderId 防重复扣减；`createRefund` 按该单 `getOrderBalanceConsumed` 封顶退款。
- 聚合单/拆单：各子单独立走 balance-pay → 各自扣减同一 顾客+渠道 账户，总扣减=应付，无重复扣减。
