# 微信支付证书配置手册（vshop / coupon-plugin）

> 适用：C 端券商城购券（`createWechatCouponPayment`）与商品订单微信支付的商户证书配置。
> 本手册**不含任何真实凭证值**；所有密钥材料只落服务器加密存储或 PM args，不进对话、不进 git。

## 1. 前置现象

未配置证书时，购券微信支付报：

```
PEM: no block
```

（Node crypto 读不到 PEM 块 = 私钥缺失或格式错。）

## 2. 材料清单（6 项）

| 文件（放 `.secrets/wechatpay/`） | 内容 | 来源 |
|------|------|------|
| `appId.txt` | 公众号/小程序 AppID | 微信公众平台 |
| `mchId.txt` | 商户号 | 微信商户平台 |
| `apiclient_key.pem` | 商户 API 私钥（PEM） | 商户平台 → 账户中心 → API 安全 → 申请 API 证书 |
| `serialNo.txt` | 商户 API 证书序列号 | 同上（证书详情页） |
| `apiv3key.txt` | APIv3 密钥（32 位） | 同上 → 设置 APIv3 密钥 |
| `platform_pub.pem` | 微信平台公钥 PEM | 同上 → 微信支付公钥（新公钥模式） |

另确认**回调地址** `notifyUrl`（建议 `https://e.joho.cn/wechatpay/notify`；tenantConfig 已有值则沿用）。

`.secrets/` 已被 `.gitignore` 覆盖，材料文件**严禁提交**。

## 3. 配置生效的双路径（字段级回落）

`wechatpay-handler.ts` 的解析顺序（L74-81）：

1. **渠道 payConfig（优先，加密存库）**：`Channel.customFields.payConfig.wechatpay`，经 `updateTenantConfig(payPatch)` 写入。租户级配置**逐字段覆盖**全站级，未填字段回落全站级（mergePayConfig）。
2. **PaymentMethod args（兜底，明文存库）**：`code:"wechatpay"` 的 method handler args（privateKey/publicKey/apiKey/...），经 `updatePaymentMethod` 写入；回调地址还可用 plugin options `notifyUrl`（env）。

⚠️ payConfig 必须写在 **C 端下单时的 ctx.channel**（`vendure-token` 对应的渠道）上，否则 override 不生效。单租户场景建议两路径写**同值**双保险。

## 4. 写入步骤（admin-api，superadmin）

登录拿 token（`Authorization: Bearer <token>`，v3.6.4 tokenMethod=bearer）后：

### 4.1 组装 patch（Node 本地脚本读材料文件，凭证不出本机）

读 6 个文件拼 `payPatch.json`：

```json
{
  "channelId": "<C端渠道id>",
  "pay": {
    "wechatpay": {
      "appId": "...", "mchId": "...", "serialNo": "...",
      "privateKeyPem": "...\n...", "apiKey": "...", "platformPublicKeyPem": "...",
      "notifyUrl": "https://e.joho.cn/wechatpay/notify"
    }
  }
}
```

### 4.2 发送（优先路径）

```powershell
node -e "const fs=require('fs');const body=JSON.stringify({query:'mutation U($input: JSON!) { updateTenantConfig(input: $input) { channelId pay } }',variables:{input:JSON.parse(fs.readFileSync('e:/zhao/vshop/.secrets/wechatpay/payPatch.json','utf8'))}});fs.writeFileSync('e:/zhao/vshop/.secrets/wechatpay/_req.json',body)"
curl.exe -s -X POST https://e.joho.cn/admin-api -H "Content-Type: application/json" -H "Authorization: Bearer <token>" --data-binary "@e:/zhao/vshop/.secrets/wechatpay/_req.json"
```

Expected：返回 `pay.wechatpay` masked（私钥/密钥打码，`mchId`/`serialNo` 可见且为新值）。
（若 schema 报类型错，先内省 mutation 签名校准：`__schema { mutationType { fields { name type { name ofType { name } } } } }`。）

### 4.3 兜底写 PaymentMethod args（同值）

```powershell
curl.exe -s -X POST https://e.joho.cn/admin-api -H "Content-Type: application/json" -H "Authorization: Bearer <token>" --data-binary "@e:/zhao/vshop/.secrets/wechatpay/_pm.json"
```

（`_pm.json` 为 `updatePaymentMethod(id, { handler: { code:"wechatpay", args:[...] } })` 的请求体。）
Expected：`{ id code:"wechatpay" enabled:true }`，无 schema 错误。

## 5. 报错对照表

| 报错 | 根因 | 处置 |
|------|------|------|
| `PEM: no block` | 商户私钥缺失 / 格式错（缺头尾行、被转义） | 检查 `apiclient_key.pem` 完整 PEM（`-----BEGIN PRIVATE KEY-----`），走文件传输避免复制走样 |
| `签名错误`（微信侧） | APIv3 密钥错 或 证书序列号 serialNo 与私钥不配对 | 核对 32 位 apiv3key；核对 serialNo 与证书详情一致 |
| `证书链错误` | 平台公钥（platform_pub.pem）不是当前商户对应的微信支付公钥 | 重新下载微信支付公钥；确认新公钥模式（非平台证书模式） |

## 6. 换证 / 新商户复用清单

1. 商户平台换发 API 证书 → 更新 `apiclient_key.pem` + `serialNo.txt`（序列号必换）。
2. APIv3 密钥变更 → 同步更新两路径（payConfig + PM args），避免回落混用新旧。
3. 切换商户号 → appId/mchId/serialNo/私钥/apiv3key/平台公钥**全量**更新，并重验回调地址归属。
4. 每次更新后跑最小真实验证：¥0.01 可售券下单 → 微信拉起 → 支付 → PAID → 发券（对应测试计划 TC-WP-1）。
5. 生产凭据管理：token 存 `.secrets/admin_token.txt`（gitignore 区），会话随服务器重启失效需重登。
