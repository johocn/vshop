# vshop 租户后台导航重构与履约配置 CRUD 设计文档

- 日期：2026-08-23
- 项目：vshop（Vendure C 端商城）web-admin 移动管理后台
- 访问地址：`https://e.joho.cn/guanli`
- 前置文档：`docs/superpowers/specs/2026-08-22-vshop-tenant-admin-design.md`（架构/登录/店铺隔离沿用）
- 本文范围：导航样式重构（☰ 抽屉 + 工作台）+ 配送/支付方式 CRUD 补齐
- 技术栈：uni-app CLI（Vue3 + Vite）+ graphql-request 直连 Vendure `admin-api`

---

## 1. 背景与问题

现网工作台/抽屉存在以下体验问题（实证于当前代码）：

1. **☰ 抽屉是纯文字列表**，无配色分区、无功能分组视觉层级，样式朴素不美观；占用行数多、一屏列不全。
2. **工作台功能平铺**，未区分高频/次频/低频，未做 strapi-backend 式的卡片/宫格专区。
3. **配送方式：只读**（`fetchShippingMethods`），无 CRUD、无启停；支付方式：仅开关（`setPaymentEnabled`），无新增/编辑/删除。
4. **导航顺序未体现依赖关系**：配送档案/支付档案本应依赖「配送方式/支付方式」与「自提点」，却平级平铺。

## 2. 目标

1. ☰ 抽屉重做为一屏点满全部功能的**密集宫格**：分业务区 + 三档标签（填充/镂空/纯文字）配色，商品区「分类」置首。
2. 工作台落地页仿 strapi-backend：KPI 卡片 + 常用功能区（一行 4 个）+ 履约/配置区 + 次频商品区 + 底部固定工具栏。
3. 配送方式 / 支付方式补齐 **CRUD + 启停**；删除二次确认、新增走弹窗。
4. 导航顺序按**前提在前、档案收尾**组织：配送/支付方式（前提）→ 自提点 → 配送档案/支付档案。

### 非目标
- 不改后端 schema（配送/支付 CRUD 走 Vendure core 已有 admin-api）。
- 不做分销模块新增。
- 不做服务端多租户硬隔离（见前置文档二期）。

## 3. 整体导航架构

### 3.1 ☰ 抽屉（全部功能 · 一屏点满）

> 左上角 ☰ 抽屉的定位 = **一键查看全部功能**，因此一屏列完、不滚动、不占大行距。

**布局**：分业务区，每区一行色带标题 + 密集换行标签（`flex-wrap`，间距 8rpx，按屏宽自适应列数，能放多少放多少）。

**业务区与三档标签配色**：

| 业务区 | 标题色带 | 分区内容 | 标签档位分配 |
|---|---|---|---|
| **商品** | 橙 `#ff6600` | 分类 · ＋新增商品 · 商品列表 · 库存预警 · 图片库 · 店铺装修 | 填充：分类、＋新增商品、商品列表；镂空：库存预警；纯文字：图片库、装修 |
| **销售** | 红 `#e53935` | 订单 · 核销码 · 配货 · 送货 · 售后 · 数据看板 · 分销 | 填充：订单、核销码；镂空：配货、送货、售后；纯文字：看板、分销 |
| **参考/配置** | 蓝 `#2563eb` | 配送方式 · 支付方式 · 自提点 · 配送档案 · 支付档案 · 我的 · 退出 | 填充：无；镂空：配送方式、支付方式、自提点；纯文字：配送档案、支付档案、我的、退出 |

**三档标签样式**：
- **✦ 填充** = 高频主功能：渐变填充 + 白字 + 主色投影，如 `#ff6600→#ff8833`（销售用 `#e53935→#ff6659`）
- **◌ 镂空描边** = 次级功能：1.5px 描边 + 同色文字（如配送/支付方式用蓝系 `#2563eb`）
- **– 纯文字** = 低频配置：灰底 `#f5f5f5` + 灰字 `#999`

**排序规则（用户确认）**：商品区「**分类**」置首，其余按频次。

### 3.2 工作台（落地页）

自上而下，遵循 uicraft「层级与间距先行、不堆装饰」：

1. **头部**：店铺 Logo + 店铺名/经营状态 + 右上角 ☰（打开 3.1 抽屉）
2. **KPI 卡片**：3 列 —— 今日销售额(橙) / 待发货(红) / 库存预警，数值大字 + "去处理 ›" 入口
3. **常用功能区**（标题带「高频」角标）：**一行 4 个**宫格（`repeat(4,1fr)`，gap 10rpx）
   - 红色：订单、核销码
   - 橙色：＋新增商品、配货、送货、售后
   - 浅色：分类、库存、装修
4. **履约 / 配置区**：两格横排 `pill` —— 配送方式 / 支付方式（标注「前提配置」）
5. **次频商品区**（标题「次频」蓝角标）：商品列表、图片库
6. **底部固定工具栏**：工作台 / ＋商品 / 订单 / 我的

> 工作台仅放高频入口；低频与全量都进 ☰ 抽屉，避免列表过长。

## 4. 配送 / 支付方式 CRUD + 启停

> 依托 Vendure core admin-api 既有 mutation：`createShippingMethod / updateShippingMethod / deleteShippingMethod`、`createPaymentMethod / updatePaymentMethod / deletePaymentMethod`；表单位于同一**全屏弹窗**中。

### 4.1 交互（用户确认两点）
- **删除加二次确认**：点「删除」→ `uni.showModal` 弹确认 → 确认才删，成功后刷新。
- **新增走弹窗**：点「＋新增」（头部或底部满宽按钮）→ 弹出全屏单表单弹窗（`uni.showModal` 不适用多字段，改用自定义全屏 `popup`/view 层），填完保存。

### 4.2 列表卡片
| 元素 | 说明 |
|---|---|
| 图标 + 名称 | 名称旁带「启用/停用」胶囊标（启用绿 `#43a047`，停用灰） |
| 副行 | `code` + 描述/规则摘要 |
| 开关 | 切启停，停用即时置灰；停用后新订单不可选 |
| 属性标签 | 如 `邮寄/自提`（蓝）、`运费 ¥10`、`时效 2-4天` |
| 操作行 | 编辑（蓝 `#2563eb`）/ 删除（红 `#e53935`，二次确认） |

### 4.3 前提提示条
列表顶部提示条：「**前提配置**：先配好配送方式，才可在『配送档案』里引用；停用后新订单不再可选。」支付方式同理。

### 4.4 支付方式页
同构复用配送方式页，仅换图标与开关语义。

## 5. 导航依赖与隐藏规则

- **前提在前**：配送方式、支付方式（前提一）→ 自提点管理（前提二，依赖「门店自提/单位自提」等自提点类型）→ 配送档案/支付档案（收尾，依赖前两者）。
- **档案入口兜底**：若某部门下「配送方式/支付方式/自提点」为空，对应档案页给出"请先配置前提"的空引导，而非显示空列表误导。
- 抽屉与工作台统一采用上述顺序输出。

## 6. 技术实现

### 6.1 涉及文件（web-admin `d:\zhao\vshop\web-admin`）
| 文件 | 改动 |
|---|---|
| `src/components/Drawer.vue` | 重写为分业务区 + 三档标签密集宫格；商品「分类」置首 |
| `src/pages/dashboard/index.vue` | 按 §4 重构工作台（KPI + 4 列宫格 + 履约区 + 次频区） |
| `src/components/BizCard.vue` | 支持 4 列密度与三档着色（填充/镂空/纯文字） |
| `src/pages/shipping/methods/index.vue` | 增 CRUD + 开关 + 前提提示 + 删除二次确认 + 新增弹窗 |
| `src/pages/payment/methods/index.vue` | 同构补 CRUD（已有开关，补新增/编辑/删除） |
| `src/apis/shipping.ts` | 补 `create/update/deleteShippingMethod` 及 `enabled` 字段 |
| `src/apis/payment.ts` | 补 `create/update/deletePaymentMethod`（保留 `setPaymentEnabled`） |
| `src/uni.scss` | 补确定性色板变量（红/蓝/镂空/填充） |

### 6.2 数据接口（Vendure core admin-api，均为既有，需本地/线上 probe 校准字段）
- `ShippingMethod`：`id code name description enabled`；`UpdateShippingMethodInput { id, enabled, ... }`
- `PaymentMethod`：`id code name description enabled`；`updatePaymentMethod(input{ id, enabled })`（已实测）
- 新增表单字段依 probe 结果而定（name/code/description/enabled 为主，深度 config 不展开做）。

### 6.3 构建/部署
沿用**部署铁律**：本地 `npm run build:h5` → web-admin 产物 → tar → scp `qing:/tmp` → 解压到 `/opt/1panel/apps/openresty/openresty/www/sites/e.joho.cn/guanli/`（备份 + `rm -rf assets` 防旧 chunk）→ curl 验证。
> 配送方法/支付方法最终是否进入"配送档案/支付档案"创建表单，属后续档案页联动，不在本文 CRUD 首页范围内（档案引用已支持传入 methodIds）。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| core admin-api 配送/支付 CRUD 字段与后端一致性问题 | 构建后 probe-live 校验，锁定字段后再提交 |
| 新增方法深度配置（calculator/handler）复杂 | 主页只做基本字段(名称/编码/描述/启停)；深度配置指引到原实例 |
| 抽屉一屏点满在窄屏溢出 | `flex-wrap` + 自适列数 + 标签缩小，必要时允许两屏滚动兜底 |

---

## 8. 结语

本设计在既有 web-admin 之上重构导航视觉与交互，补齐配送/支付 CRUD，并使导航体现「前提→档案」的依赖顺序。待用户确认后转入 writing-plans 生成实施计划。
