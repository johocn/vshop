# 商品详情页库存展示 设计文档（方案 2-D）

> **方案标识：方案 2 子项目 D（详情页展示）**。方案2 拆 4 子项目按序设计：A 库存模型 → B 物流配送 → C 对账 → D 详情页展示。
> **存续：设计定稿，随方案2 各子项目一并存档，待多方案比选后统一执行（暂缓实施）。**

## 1. 目标与范围

调整商品详情页库存展示方式，对齐虚拟/物理库存模型（方案2-A）：

1. **默认只展示商品的虚拟库存**（`saleableStock`）——所有租户一律先只显示这一个可售总数。
2. **仅开启物理库存的租户**，详情页才显示「附近库存」明细（各物理仓 + 距离 + 折叠展开）。
3. 开启物理租户其虚拟库存数 = Σ 物理库存（由 A 镜像保证，展示侧直接用 `saleableStock` 天然成立）。

## 2. 已确认决策

1. 展示数据源 = A 店铺端库存接口：`saleableStock` + `stockDetail`（零新增请求）。
2. 判定开关 = `tenant.physicalStockEnabled`（未开物理租户不渲染附近库存块）。
3. 复用既有就近库存折叠展示方案。

## 3. 数据源（消费 A 第 4 节）

- `saleableStock`：虚拟仓 onHand（对外可售数）。纯虚拟变体=独立数；物理驱动变体=Σ绑定物理仓（镜像值）。
- `stockDetail`：仅物理驱动变体返回 `{locationId, 名称, 坐标, onHand}` + 按当前客户地址距离/就近排序。
- `tenant.physicalStockEnabled`：随租户上下文下发。

## 4. nshop 详情页接入

- 库存展示块默认态：仅显示「虚拟库存 X 件」（`saleableStock`，含缺货态「已售罄」）。
- 开启物理租户 + 物理驱动变体：显示「附近库存」行 → 展开明细（物理仓名 + 距离 + onHand + 就近排序，沿用既有折叠样式与 i18n）。
- 未开启物理租户：仅虚拟数（与现状一致）。
- 多版式兼容：库存块在所有版式（classic/floor/dualBuy/hotel）通用，只改数据源不改版式结构。

## 5. 边界

- 纯虚拟变体（物理租户内）：只显示虚拟库存，无附近明细（无绑定仓）。
- `stockDetail` 空 / 坐标缺失：附近行隐藏；距离缺失排后。
- 已售罄判定基于 `saleableStock`（镜像保证恒等，仅防御）。
- 展示侧不改库存数据，修正走 A/C 业务入口。

## 6. 测试与交付

- 前端：三种租户态（未开启物理 / 开启物理·物理驱动变体 / 开启物理·纯虚拟变体）截图与断言。
- 接口纯度：`saleableStock`/`stockDetail`/`physicalStockEnabled` 返回正确。
- 两端构建 + 部署 + GraphQL 冒烟 + 手机视口回归 + 操作手册 op-20。

## 7. 非目标（YAGNI）

- 前端展示多仓合并购买、省市区库存筛选等 OTA 高级能力。
- 实时库存轮询（当前按详情加载时点展示）。
