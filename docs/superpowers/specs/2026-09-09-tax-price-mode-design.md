# 税率三档 + 价格/划线/成本与库存联动设计

> 设计日期：2026-09-09
> 状态：已获用户批准（brainstorming 流程）
> 涉及仓库：vendure（后端）、web-admin/vshop（运营端）、nshop（C端）

## 1. 背景与问题

商品价格与税率关系长期存在不一致：运营端录入价（净价）在部分渠道被当作含税价处理，关闭税率后 C 端展示价格被税吃掉 13%（录入 200 显示 176.99）。此前通过「运营端保存按税率换算」「存量校准脚本」等局部修复缓解，但**根因是缺少统一的价税口径模型**。

本次一次性确立三档税率方式，统一定义「运营端录入值」与「C 端展示/结算」之间的换算关系，并补齐划线价、成本价的录入与联动。

## 2. 目标

1. 税率开关由布尔 `taxEnabled` 升级为**三态**：含税价 / 零税价 / 不含税价。
2. **运营端录入的净价/划线价/成本价保持不变**；C 端仅按税档换算展示。
3. 商品基础信息新增**划线价、成本价**（价格已存在），保存时自动填入变体；变体内可独立改价改库存，不影响基础信息。
4. C 端商品价格、划线价格按「是否含税」换算后展示；结算环节税率同理。

## 3. 核心规则（用户批准的语义）

设运营端录入：价格=200，划线价=300，成本价=160，库存=100。

### 3.1 C 端展示

| 档位 | 现价 | 划线价 | 说明 |
|------|------|------|------|
| **A 含税价** | ¥200 | ¥300 | 录入价原样展示，价内含税 |
| **B 零税价** | ¥200 | ¥300 | 录入价原样展示，免税 |
| **C 不含税价** | ¥226 | ¥339 | 录入价 × 1.13 展示，价税分离 |

> 换算系数来自默认税率（当前生产仅 13% 一条），动态读取。

### 3.2 结算小计（买 1 件 200 元商品）

| 档位 | C端单价 | 税额 | 应付总额 | 行为 |
|------|------|------|------|------|
| **A 含税** | 200 | +23.01（显示） | **200** | 价内含税，账面拆税额展示（200÷1.13×0.13≈23.01），**不额外加收** |
| **B 零税** | 200 | 0（不显示税额行） | 200 | 免税 |
| **C 不含税** | 200 | +26 | **226** | 价税分离，真实额外加收 200+26=226 |

**关键差异**：A 结算页多一行「税额 23.01」展示但应付仍 200（价内已含税拆给用户看）；B 不显示税额行应付 200；C 真实价税分离应付 226。

## 4. 实现方案（已选：方案一 — 前端纯展示层换算 + 后端三态）

### 4.1 数据模型

**后端 Vendure**：
- `Channel.customFields.taxEnabled: Boolean` → 迁移为 `Channel.customFields.taxMode: String`，枚举 `inclusive`（含税价）/ `zero`（零税价）/ `exclusive`（不含税价）。
- `ChannelTaxLineCalculationStrategy` 依 `taxMode` 返回：
  - `inclusive` → 走默认单税率计算，价内拆税（unitPriceWithTax = price，TaxLine 拆出税额）。
  - `zero` → 返回空 TaxLine[]，零税率，unitPrice == unitPriceWithTax == 录入净价。
  - `exclusive` → 价税分离：price 存净价，按税率加税，unitPriceWithTax = price × (1 + rate)。
- 税率系数来自默认 TaxRate（`value=13`），与 `fetchTaxRatePercent()` 一致。

**运营端（web-admin）**：
- 变体增加三值（net/list/cost）的持久化字段：`netCents`（净价分）/ `listCents`（划线价分）/ `costCents`（成本价分），保存为**净基准值，永不被税换算改写**。

**C 端（nshop）**：
- 读 `netCents`/`listCents`，依 `taxMode` 纯函数换算展示现价与划线价。

### 4.2 换算纯函数（前后端共用同一逻辑）

```
grossFromNet(net, rate) = net × (1 + rate/100)      // exclusive 档 C 端展示
if taxMode == inclusive || zero: 展示 = netCents                      // 原样
if taxMode == exclusive:                展示 = grossFromNet(listCents)  // ×1.13
划线价同理应用同一系数。
```

### 4.3 运营端表单与联动

**基础信息 Tab** 新增两栏：划线价（元）、成本价（元）。价格、库存已存在。

**规格变体 Tab** 联动规则（四值：划线价 / 价格 / 成本价 / 库存）：
- 基础信息保存 → 四值自动填入变体对应行。
- 变体单行可独立改价/改库存 → **不影响**基础信息值。
- **已独立改过的行，之后基础信息再改不再覆盖它**（按变体行去重记忆：首次由基础信息带入为「未改」，行内手动编辑后标记「已改」）。

### 4.4 C 端展示位置
- 商品详情/列表价格区：现价 + 划线价，按 §3.1 换算。
- 结算页：现价、税额、应付总额按 §3.2。

## 5. 影响面与边界

- **A 与 B 在应付金额上相同**（200），仅 A 额外展示税额行，B 无。这与早期"仅 C 特殊"略有细化，以用户最后确认（A 结算显示税额）为准。
- 历史数据：方案一的净基准字段是新增字段，历史商品在不重填前使用旧 price 口径；建议另做一次校准（沿用 `calibrate-prices.mjs` 思路）补 net/list/cost 值。**本次设计不含迁移脚本，作为计划期可选任务。**
- 关闭税率的存量租户（如 t2）此前靠布尔 `taxEnabled=false` 生效，需迁移到 `taxMode=zero`，保证行为不回退。

## 6. 验收要点

1. 后台三档切换生效，C 端按 §3.1 展示。
2. 运营端录入净价后，C 端在 A/B 显示录入价、C 显示录入价×1.13。
3. 结算：A 显示税额 23.01 应付 200；B 无税额应付 200；C 应付 226。
4. 基础信息保存四值填入变体；变体独立改价不改基础信息；已改行不被覆盖。
5. 存量租户 t2 迁移至 zero 后行为不变。
