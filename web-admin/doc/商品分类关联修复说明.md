# 商品「选分类保存即关联」修复说明

## 背景问题

运营后台**新建/编辑商品**时，表单里选了「分类」（collectionId），但保存链路只写 `collectionId` 与 `tenantCategoryRef`（名称字符串自定义字段），**从不把商品加进该分类（Collection）的 `product-id-filter` 过滤器**。导致该分类的成员永远不变——例如「休闲娱乐」分类始终只有最早手动塞进的 1 件商品。

## 根因机制

- 决定「C 端某分类下有哪几件商品」的是 Collection 的 `filters`（`product-id-filter` 过滤器列表）及其异步重算的**变体成员**。
- `SetProductPlatformCategory`（平台手动归类）只打 `platformCategoryId`/`needsCategorization` 元数据、**不动过滤器**。
- 前端 `updateCollection` 全仓库无调用方。→ 分类成员长期静态。

## 修复内容

- **`src/apis/collection.ts`**：新增 `mapProductToCollection(productId, collectionId)`，调用后端 cjk-plugin 已有 mutation `mapProductToPlatformCollection`。
- **`src/apis/product.ts`**：
  - `ProductSaveInput` 新增 `collectionId` 字段。
  - `createProductFull` / `updateProductFull` 末尾，当 `input.collectionId` 存在时调用 `mapProductToCollection`。
- **后端（无需改，仅复用）**：`TenantCatalogAdminResolver.mapProductToPlatformCollection` → `TenantCatalogService.addProductToCollection`，该函数幂等地把商品 ID 追加进分类 `product-id-filter`，并调用 `collectionService.triggerApplyFiltersJob` 触发异步成员重算。

## 部署

web-admin 本地构建 → `scripts/deploy.mjs`（scp → 服务器解压 → nginx reload）。生产 `e.joho.cn/guanli` 已生效。

## 回归验证（生产，t2 渠道）

用超管 + t2 渠道上下文调用 `mapProductToPlatformCollection(productId=61, collectionId=14)`：

- 关联前：`休闲娱乐(14)` 成员数 = 1（变体 58，属商品 60 温泉票）
- 调用后 5s：成员数 = 2（新增变体 64「验收商品-图片库存11351」）
- 过滤器由 `["60"]` 更新为 `["60","61"]`，异步 `applyFiltersJob` 正常消费，**成员增长验证通过**

结论：商品保存选分类后即可建立商品→分类关联，分类库存商品数随之增加。

> 注：本修复位于运营后台保存链路，无可见 UI 变化，不涉及 C 端前台；手机视口交付截图不适用。
