二、三种做法（实现取向，非批次结构）

A公共层抽取 + 就地对齐推荐
列表抽 useListPage() composable（分页游标 / 筛选态 / 下拉刷新 / 加载更多 / 空态），售后 · 流水 · 单据中心 · 报表复用同一套。新增列表页直接接入，不再各自手写。
分类走 Vendure 原生 updateCollection（position + parentId），不新增本地排序字段；原生能力不足则降级「仅层级展示 + 仅排序」。
报表并入既有 pages/data/dashboard，新增一层「视图」分段（经营数据 / 作业分析），复用现成图表与 7·30 天筛选。
定时在 cjk-plugin 注册 JobQueue + 独立 worker 入口脚本，复用仓库既有 npm run dev:worker 约定。
取舍一次性消除列表标准分裂后续页面零成本对齐需先搭 composable 再改页
B逐页就地改造
列表售后列表单独补筛选 + 分页，照抄订单列表写法；不动公共层。
分类同 A（原生 position / parentId）。
报表新增独立「作业报表」页，独立入口。
定时同 A。
取舍改动面最小 / 风险最低列表两套标准继续分裂第 5 轮还要再对齐一次
C抽列表页脚手架组件
列表做成 <ListPage> 模板组件（工具栏 / 筛选抽屉 / 分页 / 空态用 slot 拼装），页面只写业务行。
分类同 A。
报表同 A。
定时同 A。
取舍一致性最强uni-app 下 slot 抽象易踩坑改造面最大 / 回归面最大

三、逐轴对照

决策轴A 公共层抽取B 逐页改造C 脚手架组件
列表分页/筛选复用composable 复用复制粘贴组件 + slot
改动文件数中少多
后续新页成本低高最低
uni-app 兼容风险低低中（slot / 作用域）
回归面可控（4 页）最小（1 页）大
分类 position/层级A / B / C 一致：优先 Vendure 原生，不可用则降级
报表落点并入数据看板（新增视图分段）独立报表页并入数据看板（新增视图分段）
